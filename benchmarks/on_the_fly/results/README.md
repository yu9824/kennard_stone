# Results: core vs on-the-fly prototype (issue #41)

Generated by `bench.py` (raw data: `cpu.jsonl`, `gpu.jsonl`).

- Machine: MacBook Air, Apple M4 (10 cores), 16 GB memory, macOS 26.7.2.
- CPU runs: Python 3.12, numpy 2.4 with OpenBLAS (10 threads by default), scikit-learn 1.8.
- GPU runs: Python 3.10, PyTorch 2.11 on MPS, scikit-learn 1.7.
- Data: standard normal, 8 features. Each run in a fresh process.
- Modes: `single` = `n_jobs=None` and one BLAS thread for both; `parallel` = `n_jobs=-1`; `gpu` = `device="mps"`.
- "RSS increase" is the peak RSS during the selection minus the peak before it. "same result" compares the selected indexes.
- The core was not run with 40,000 samples (the distance matrix alone needs 12.8 GB). The prototype was run on the GPU only up to 10,000 samples because it is very slow there.

## Findings

- CPU: the prototype uses almost no extra memory (about 30 MB instead of about 3 GB at 20,000 samples) and is as fast as the core from 10,000 samples on (slower below, but by fractions of a second). The results are identical in every CPU run.
- Both implementations spend most of their time in the Python part of the selection loop, not in the distance computation.
- GPU: the prototype is 6 to 97 times slower and uses more memory, because it launches a small kernel and copies one row back per step. From 5,000 samples on, its results differ from the core (float32, and torch.cdist switches algorithms with the matrix size), so it is not usable in this form.
- Equivalence (`check_equivalence.py`, CPU): 256 of 271 cases identical; the 15 others differ only in the order of near ties, and both results satisfy the max-min criterion.
